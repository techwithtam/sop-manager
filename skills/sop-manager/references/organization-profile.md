# Organization profile

An organization profile is optional configuration. It lets a team adapt presentation without changing the plugin's evidence and safety rules.

## Supported preferences

- organization name for document headers;
- preferred document voice and reading level;
- names for Core Process, SOP, Work Instruction, and Checklist;
- required or prohibited section labels;
- role and system terminology;
- document ID and version conventions;
- default review frequency;
- approval and compliance-review roles;
- formatting preferences; and
- approved status labels that map clearly to the plugin's draft and approval states.

## How to use it

Use preferences only when the user supplies them in the current conversation or points to a clearly selected profile they are authorized to use. Summarize the active preferences before the first draft. If multiple profiles exist, ask the user to select one.

Do not search unrelated workspace content for preferences. Do not treat an example SOP as an organization-wide standard unless the user confirms it.

## Default when no profile exists

Use the neutral operational voice and standard templates bundled with the plugin. Do not delay drafting for branding, terminology, or formatting preferences that do not affect safe execution.

An organization profile cannot override privacy restrictions, evidence requirements, human approval, Approved-only retrieval, or database scope.
